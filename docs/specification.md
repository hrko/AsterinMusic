# 現行仕様・要件

接続・動作設定はYAMLを使用する。[設定ファイル仕様](configuration.md)を参照。現在は1Bot・1サーバーに限定し、複数指定を拒否する。

2026-11-02時点の実装を基準とする。利用者から見た動作の参照先は本書とし、過去の検証結果は[文書一覧](index.md)から参照する。

## 対応範囲とURL

主な用途はDiscord通話中のBGM。対象サイトはYouTube、YouTube Music、ニコニコ動画。取得対象は公開・限定公開として取得できる通常動画で、ライブ中・配信予定・認証が必要な動画は対象外とする。アカウントCookieを前提としない。

YouTubeの通常動画・Shorts・短縮URL、YouTube Musicの動画、ニコニコ動画の`sm` / `nm` / `so`形式と短縮URLを扱う。通常プレイリストの取り込みはYouTube / YouTube Musicに限る。

yt-dlpへ渡す前にURLを再構築する。動画ID、取り込みに使うリストIDだけを用途に応じて保持し、`si`、`utm_*`、`index`、再生開始時刻などの追加パラメーターとフラグメントは引き継がない。HTTP入力もHTTPSの正規URLへ変換する。認証情報・明示的なポート・ローカルファイル・未対応サイトのURLは受け付けない。

## コマンドと操作

Botは設定した1サーバーで動作する。追加・再開・停止・スキップ・キュー消去・音量変更・自動再生のON/OFFは、利用者が音声チャンネルに参加していることを確認する。Botが接続中なら同じチャンネルから操作する。キュー・再生中の曲・音量・自動再生状態の参照は、音声チャンネルへの参加を必要としない。リスト取り込みボタンには追加者本人の確認もある。

| コマンド | 動作 |
| --- | --- |
| `/play url:URL` | 単曲またはプレイリストを追加し、再生開始 |
| `/playnext url:URL` | 単曲を自分の待機曲の先頭に追加。URL必須 |
| `/play` | 保持している待機キューを再開 |
| `/mix url:URL count:20` | 動画を起点にMixを追加。起点を含め既定20曲、1〜50曲 |
| `/stop` | 再生中の曲を終了して切断。待機キューは保持 |
| `/skip` | 次の曲へ移動 |
| `/queue page:1` | 公平な再生予定順を10曲ずつ表示 |
| `/queue action:clear` | 待機キューを全消去 |
| `/nowplaying` | 曲・追加者・送信済み時間・音量を表示 |
| `/volume percent:30` | 音量を変更。省略時は現在値を表示 |
| `/autoplay on` | 手動キューが空のときの自動補充を有効化 |
| `/autoplay off` | 補充を停止。現在再生中の曲は継続 |
| `/autoplay status` | ON/OFF、起点、取得状態、有効化した利用者を表示 |

## 自分の次の番への追加

`/playnext`は自分の待機曲の先頭へ単曲を追加する。再生中の曲は中断せず、他の追加者との交代順も変更しない。自分に待機曲がない場合は通常の追加と同じ規則で巡回に参加する。X、Yの順に連続して先頭追加すると、自分の曲列は`Y → X → 既存曲`となる。

A1が再生中で、待機順が`B1 → A2 → B2 → A3`のときにAさんがXを追加すると、待機順は`B1 → X → B2 → A2 → A3`となる。追加完了メッセージにも、自分の待機曲の先頭への追加であり、他の追加者との交代順を維持することを表示する。

単曲に付属するリストは追加後のボタンで取り込める。リスト専用URLを直接先頭追加する操作と、`/mix`の先頭指定は対象外。取得失敗時はキューを変更しない。容量・操作権限・永続化は通常追加と共通で、実際に再生されたYouTube曲は自動再生の起点にもなり得る。

付属リストは取り込み確定時に元の曲が待機中ならその直後へ挿入する。元の曲が再生中・再生済み・削除済みなら、`/playnext`由来は自分の先頭、`/play`由来は末尾へ追加する。詳細は[リスト追加](playlist-button.md)を参照。

## プロフィールの再生中表示

`bots.<name>.activity.enabled`は既定で`true`。設定対象と実際の参加先が同じ1サーバーの場合に限り、BotのListeningアクティビティに曲名を表示する。設定外サーバーへの参加、参加状況が未確定・利用不可の場合は表示を消す。将来複数サーバーを設定したBotも、現在の再生数に関係なく表示しない。再生数などの集約表示も行わない。

音声送信開始後に表示し、準備中・終了・スキップ・停止・切断時は消去する。曲名は最大128文字に省略する。Presenceはサーバー限定公開ではない。更新は1秒間隔で最新状態を確認し、送信間隔は最低5秒。反映にはこの待ち時間とDiscord側の遅延が生じる。更新失敗は再生に影響させず、最新状態で再試行する。起動・Gateway再接続時も再計算し、表示内容は保存しない。

## 音量・ビットレート

音声のOpus目標ビットレートは接続先チャンネルの`bitrate`に従う。再生開始時と各20msフレームの変換前に最新のチャンネルキャッシュを参照し、再生中の設定変更も反映する。取得できない場合はその曲で直前に適用した値を維持し、初回から取得できない場合は96kbpsを使う。有効範囲は8〜384kbps。CVBRを使うため、パケットごとのサイズは一定ではない。

音量は既定の初期値が30%（−28 dB、振幅比約0.0398）です。1〜100%を−39.6〜0 dBへ線形に対応させ、0%はミュートとします。変更時には10msのフェードを適用します。音源ごとのラウドネス正規化は行いません。

1〜100%の値をpとすると、`dB = 40 × (p / 100 − 1)`、振幅倍率は`10^(dB / 20)`です。50%は−20dB（振幅10%）になります。100%を超える増幅は行いません。設定は送信直前の20msフレームに適用し、連続操作では最新の設定を使います。Discord側のバッファーや端末の遅延は別に生じます。

## 公平キューと再生順

手動追加曲は追加者ごとに追加順を維持し、追加者同士で1曲ずつ交代する。再生開始時にその人を巡回順から取り出し、曲の終了時に残曲があれば最後尾へ戻す。再生中の人が追加しても次の順番を先取りしない。新しい追加者は現在待っている追加者の最後尾に入る。既に待機中の追加者は、その人の曲列に追加するだけで巡回順を変えない。

AさんのA1が再生中で、A2・A3が待機している例では、次の順になる。各行は別の状況を示し、以後の追加がないものとする。

| A1の再生中の状況 | A1終了後の順番 |
| --- | --- |
| 他の人の曲がない | A2 → A3 |
| BさんがB1・B2を追加 | B1 → A2 → B2 → A3 |
| Bさんの追加後にCさんがC1を追加 | B1 → C1 → A2 → B2 → A3 |

再生中の曲へは割り込まない。公平性は曲数単位で、曲の長さや過去の累計再生時間は配分に使わない。スキップ・通常の停止・再生失敗もその人の1回の順番を終える。プロセス終了による中断は後述の再起動復元として扱う。

単曲、通常プレイリスト、Mixからの明示的な追加はすべて手動追加に含める。自動再生曲はこの巡回に入らず、手動キューが空のときだけ選択する。`/queue`は再生中の曲を除いた待機順を表示するが、順番の計算には再生中の追加者も考慮する。新しい追加によって表示後の予定順は変わり得る。

待機キューは既定で全体500曲、1回のプレイリスト取得は先頭100項目までです。追加者内では追加順を保ち、追加者同士をラウンドロビンで再生します。3曲連続で取得・再生に失敗すると停止し、残りは保持します。待機キューが空、または音声チャンネルに人がいない状態が60秒続くと切断します。手動追加キューは変更ごとに保存し、再起動後も追加者と公平な順番を復元します。ボタンの状態は再起動で失われます。

## 停止・再起動と永続化

管理タスクの`bot-restart`は再生／停止状態、音量、自動再生ON/OFF・有効化者・起点・直近50曲の履歴、音声・通知先チャンネルを保存します。再生中だった場合は接続先へ再接続し、曲の先頭から再開します。自動再生中の曲も自動再生がONなら再試行しますが、手動キューを優先します。停止中は停止状態を維持します。再生位置、取得済み音源、未再生の自動再生候補、ボタン状態は復元しません。`/stop`や`/skip`で明示的に止めた曲は再開対象に含めません。

`bot-stop`も設定を保存しますが、続く`bot-start`は自動再接続せず、URLなしの`/play`で再開します。保存失敗時は管理タスクが停止を拒否します。異常終了時や旧版からの初回移行では追加状態を保存できず、手動キューのみの復元になる場合があります。接続失敗時はキューを保持し、`/play`で再試行できます。

保存先は既定で`.rainmusic/state/<アプリID>-<サーバーID>-queue.json`です。YAMLの`runtime.state_dir`で変更できます。開発環境は従来の`.dev/state`を明示指定しています。同じ保存先を複数のBotプロセスで同時使用しないでください。曲情報・追加者情報を含むため、Git管理外の場所を指定してください。保存は一時ファイルの同期後に置換します。破損した保存ファイルがある場合は起動を中止し、そのファイルを保持します。保存に失敗した場合はログに記録し、メモリ上のキューを維持しますが、最新変更の復元は保証できません。旧版のメモリ内キューは初回移行時に復元できません。

## プレイリストとMix

動画とリストの両方を含むURLは最初に単曲だけを追加し、追加完了メッセージのボタンで残りを取り込みます。[詳細仕様](playlist-button.md)を参照してください。

Mix付き動画URLでは「Mixから追加（最大20曲）」ボタンを表示します。ボタンは追加済みの起点を除外し、重複しない候補を最大20曲追加します。`/mix`はMixのない動画URLでも生成を試み、既存のMixがあればそちらを使用します。起点の動画を先頭に含め、指定件数まで追加します。対象はYouTube / YouTube Musicの動画URLです。

Mixの候補は先頭100件まで取得し、取り込み内では動画IDで重複を除外します。既存キューとの重複は許可します。取得できた曲は実行者の曲列に追加し、公平な順番で再生します。曲目・曲順はブラウザと異なる場合があり、自動補充は行いません。Mixを取得できなければ単曲追加へ切り替えず、キューを変更しません。

## 自動再生

自動再生はサーバー単位で既定OFFです。有効な間に最後に音声送信が始まった、手動追加のYouTube／YouTube Music曲を起点にMix候補を取得します。通常プレイリスト、`/mix`、Mixボタンから取り込んだ曲も手動追加として扱います。自動追加曲とニコニコ動画は起点を変更しません。有効化時に対象の手動曲を再生中ならその曲を採用し、それ以外は起点待ちになります。

候補は手動キューとは別に保持し、手動キューが空のときだけ1曲ずつ再生します。取得・再生準備中に手動追加があれば手動曲を優先し、既に自動追加曲の再生が始まっていれば、その曲の終了後に切り替えます。直近50曲の再生履歴と候補内の動画ID重複を除外します。履歴は手動・自動の両方を含み、OFF→ONや起点変更でも保持します。

曲数・時間・無操作時間の上限は設けません。候補取得は最大100件・45秒で、候補を選べなければ追加でもう1回だけ取得し、それでも選べなければOFFにします。自動追加曲が3曲連続で失敗した場合もOFFにして通知します。`/stop`、切断、無人状態60秒でOFFになります。管理タスクの再起動では保存状態を復元します。起点待ちの空キューは通常の60秒切断を適用し、候補取得中は取得タイムアウトで判断します。

`/queue action:clear`は手動キューだけを消去し、自動再生の状態は変更しません。`/autoplay off`は未再生候補と取得処理を破棄します。起点が変わったときも古い候補を破棄します。`/nowplaying`には自動追加であることと、有効化した利用者を表示します。

## 取得・再生の制限と失敗時の動作

| 項目 | 現在の値・動作 |
| --- | --- |
| 待機キュー | 既定で全体500曲。再生中の曲は別枠 |
| 再起動時の中断曲 | 待機列の先頭へ戻すため、一時的に501曲になる場合がある。容量が空くまで追加不可 |
| 通常プレイリスト | 先頭100項目まで。取得不能項目や起点除外分を101項目目以降で補充しない |
| Mixの候補取得 | 先頭100候補まで。追加件数はボタン20曲、コマンド既定20曲・最大50曲 |
| メタデータ取得 | 既定45秒のタイムアウト |
| 音声の先読み | 1曲256MiBまでの一時ファイル。取得完了を待たず読み出す |
| DAVE鍵交換 | 最大15秒待機。完了しなければ再生エラー |
| 単曲の取得・再生失敗 | 通知して次へ進む。手動再生で3曲連続失敗すると停止し、残りを保持 |
| プレイリストの部分失敗 | 取得できた項目を追加し、検出できた除外件数を通知 |
| 音声接続失敗 | 追加済みの手動曲をキューに保持し、再開を待つ |

取得不能件数はyt-dlpが返した情報から検出できた範囲であり、サイト上の全削除項目の件数を保証しない。先頭100項目を取得した場合は、それ以降の存在を確認できなくても上限到達として表示する。

`/nowplaying`の経過時間は音声送信側の進行であり、利用者の端末で聞こえた時刻とは一致しない。鍵交換待ち・通信・端末バッファーによる差が生じる。

## 更新と運用の要件

yt-dlpの最新版を起動時と24時間ごとに確認し、ログへ記録する。適用は自動では行わず、運用者が検証・選択した版を次回起動時から使う。更新・切り戻し手順は[開発・運用手順](development.md)に記載する。

開発はWindows/Linuxに対応し、依存バージョンはmise.lockおよびgo.mod/go.sumで固定する。起動・停止は管理タスクを使用し、重複起動や確認不能なプロセスに対して追加起動・自動強制終了で対処しない。標準Bot本体はCGO非依存とし、外部コマンドとの境界は[アーキテクチャ](architecture.md)に記載する。

## 対象外と未検証条件

現在の対象外は、Spotify、ニコニコ動画のリスト一括取り込み、ログイン必須コンテンツ、ライブ配信、文字列検索、シーク・一時停止、音源ごとのラウドネス正規化。新しい機能として合意するまでは対応済みと扱わない。

実装済みでも、YouTube Music専用カタログ・プレイリスト、多人数での連続入退室、長時間運転、Linuxからの実Discord接続などは検証範囲に制限がある。Pure Go DAVEの相互運用・Windowsでの再生と再参加は確認済みだが、第三者のセキュリティ監査を代替するものではない。具体的な条件と測定結果は[検証記録一覧](index.md)を参照する。
