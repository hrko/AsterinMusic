# helpコマンドの要件

## 目的と対象

`/help`から、目的別のガイドとコマンドリファレンスを参照できるようにする。初めて再生する人には操作の流れを、指定方法を調べたい人には引数と動作を案内する。本書は実装前の合意事項であり、現行の動作は[仕様書](specification.md)、共通の表示方針は[UI設計指針](ui-guidelines.md)を参照する。実装時に現行文書も更新する。

対象は利用者向けの日本語ヘルプとする。管理タスク、認証情報の設定、内部実装、翻訳機能は対象外とする。ヘルプのために再生セッションを作成せず、再生・キュー・設定を変更しない。外部動画サイトへの問い合わせも行わない。

## 呼び出しとページの直接指定

`/help`はVC未参加・停止中・再生中のいずれでも利用でき、応答は実行者だけに表示する。任意の文字列引数`page`を設け、省略時は基本画面、指定時は対象のガイドまたはコマンド詳細を表示する。

`page`にはオートコンプリートを付ける。「再生」や`play`など、ページ名・コマンド名・短い説明から候補を探せること。候補名は「ガイド：再生・追加」「コマンド：/play — 曲の追加・再開」のように種類を区別する。空入力でも候補を提示し、並び順は安定させる。

ページの値には`guide:add`、`command:play`などの固定IDを使い、表示名と分離する。候補以外の値や廃止されたIDは検証し、無効な場合は短い案内と基本画面を表示する。入力原文をそのまま応答に埋め込まない。検索の結果なしと、無効な値での実行は区別する。

## 画面構成と移動

すべての画面を画像なしのEmbed一つで表示し、その下に二つのセレクトメニューを置く。

- 「ガイドを選ぶ」：基本の使い方と各カテゴリ。
- 「コマンドの詳細を調べる」：コマンド名と短い説明。

どちらのメニューも全画面から利用できる。選択時は同じメッセージを更新し、ガイドを経由せずコマンド詳細へ移動できる。「基本の使い方」でトップへ戻る。ページ送り、閲覧履歴、戻る／進むボタンは設けない。現在のページを該当メニューで示し、もう一方のメニューに過去の選択が残って現在地と誤認されないようにする。

画面操作は実行者に限定する。有効期間と期限切れ対応は既存の本人専用UIに合わせ、採用した期間を実装時に明記する。期限切れ・Bot再起動などで操作できない場合、応答できる範囲で本人に`/help`の再実行を案内する。公開チャンネルへ通知を追加しない。

## 基本画面とカテゴリガイド

基本画面はWebhookで選定したA案（カテゴリ別の箇条書き）とする。冒頭にVCへの参加と`/play`へのURL指定を案内し、曲の追加、再生操作、曲の確認、関連曲の再生を短い一覧で示す。

| ガイド | 掲載内容 |
| --- | --- |
| 基本の使い方 | 再生開始の手順と主要操作の一覧 |
| 再生・追加 | 通常追加と先頭追加の使い分け、単曲・プレイリスト・付属リスト |
| 再生操作 | スキップ・停止・再開・音量、停止時に保持されるもの |
| キュー・履歴 | 表示・ページ移動・履歴からの再追加、閲覧条件 |
| Mix・自動再生 | 有限件の取り込みと継続的な自動再生の違い、起点と手動曲の優先 |

カテゴリガイドは操作の流れと使い分けを説明し、引数の一覧・範囲・既定値はリファレンスへ分ける。ガイドだけでも基本操作ができる内容とする。再生の中断、キューの消去、他の人の順番への影響など、操作判断に不可欠な説明は両方に載せてよい。

カテゴリ本文の細かな配置は未確定であり、過去の比較案をそのまま採用済みと扱わない。見出しと箇条書きを基本に短い説明文を補い、ガイドとリファレンスの役割を分けた内容で実画面を確認する。

## コマンドリファレンス

一コマンドを一画面にまとめる。登録される利用者向けコマンドすべて（`/help`自身を含む）を対象とし、サブコマンドは親コマンドの画面で説明する。

| 要素 | 表示規則 |
| --- | --- |
| タイトル・概要 | コマンド名と、何をするかの短い説明 |
| 書式 | 言語指定なしのコードブロック。任意部分を角括弧で囲む |
| 省略記法の補足 | 任意部分がある場合だけ、書式の下に「角括弧内は省略できます。」をsubtextで表示 |
| 引数 | 一件でも箇条書き。必須／任意、指定範囲・選択肢、既定値、説明を掲載。引数なしなら欄を省略 |
| 動作 | 結果や条件による違いを箇条書きで説明 |
| 使用例 | 一件でも箇条書き。項目ごとに目的を示し、コマンドをコードブロックで表示 |
| 利用条件 | VC参加など、実際に必要な条件を掲載 |

書式・使用例のコマンドはインラインコードやコマンドリンクに置き換えない。コードブロック直後のsubtextは余分な空行を挟まず、Discordが描画する余白は許容する。比較用の案名や「表示サンプル」の注記は本番には載せない。

## 共通の内容・保守方針

Embed色は既存の情報表示と統一する。ガイド本文のコマンド名は可能ならコマンドリンクとし、登録IDが取得できない場合は通常のコード表記に戻す。再生中の曲、ユーザー名などの動的な状態は載せず、設定で変更可能な既定値を現在値のように示さない。

コマンド名、引数、必須判定、指定範囲などの機械的な情報は登録定義と共有する。ページ定義はオートコンプリート、二つのメニュー、直接指定、画面表示で共有し、入口による内容のずれを防ぐ。ガイド文章・使用例は別途管理し、将来翻訳できるように表示処理と分離する。汎用翻訳基盤の導入は今回求めない。

## 検証と完了条件

実装済み・実画面確認待ち：ガイドと登録定義に基づくリファレンス、ページ検索、本人専用の二つのメニューを追加した。有効期間は表示開始から15分で、画面移動では延長しない。再起動前の画面も再実行を案内する。コマンドリンクはGateway接続前に登録IDを一度取得し、取得できない場合はコード表記を使う。

2026年11月5日、コマンド登録と曲切替時の管理再起動を完了し、単一の管理プロセス・ready=trueを確認した。全体チェック（sqlc、vet、通常／音声ビルドのテスト、Windows/Linuxビルド）を通過した。コマンド・コンポーネント・オートコンプリートのイベントテストで本人限定応答、既存メッセージ更新、所有者確認、候補の一致、再生セッションに触れないことを検証した。期限・再起動識別子、表示上限、登録定義と使用例の整合性も自動テスト済み。PC／スマホの実表示と実際の操作はユーザー確認待ちであり、完了とは扱わない。

- VC未参加・停止中・再生中でも本人専用の応答が返り、再生状態を変更しない。
- `page`省略、各ページの直接指定、候補検索、無効な指定を検証する。候補とメニューから同じページに到達できる。
- すべての画面で両メニューを使え、同じメッセージの更新、現在地の表示、基本画面への移動、期限切れ案内が正しく動く。
- コマンド・引数・動作の説明を現行仕様と照合し、登録定義やページ定義の変更による不整合をテストで検出する。
- PC／スマホで見出し、箇条書き、subtext、コードブロック、長いURLの表示を確認する。文字数上限内に収め、必要な説明を機械的に切り捨てない。
- Webhookで確認できるのは主にEmbedの見た目である。本人限定表示、メニュー操作、オートコンプリート、コマンドリンクは実Botで確認する。

実装と検証が完了したら、仕様書へコマンドと利用方法を反映し、未確認の条件は明記する。
