# トレース計装の検証記録

導入途中の記録であり、[計装方針](tracing-plan.md)の完了を意味しない。基本実装は`76a28ae`時点。実機の識別子・曲情報・時刻・生ログはここに転載しない。

## 確認済み

- `internal/telemetry`のテストで、明示設定のOTLP送信、環境変数による送信先・resourceの混入防止、親子関係、無効時のno-opを確認した。
- 収集先停止、遅延、送信キュー満杯をローカルHTTPで再現した。満杯では送信完了を待たずspanを破棄する。shutdownの最大3秒の期限後には、SDKの残りの排出処理から新しいHTTP送信を始めず、送信中の通信もキャンセルする。
- SDK診断の合成秘密情報の除去と、連続エラーの出力制限を確認した。
- `TestVoiceTransportTraceFaultStages`で実際のGateway接続コードをローカルTLS/WebSocket相手に実行した。Gateway拒否、UDP探索失敗、通信鍵応答の欠落、DAVE未準備を注入し、失敗段階だけがErrorになること、先行段階の成功、spanの終了、秘密情報の非記録、DAVE資源の解放を確認した。UDP探索失敗はライブラリ内部で処理されるため、トレースではUDP／プロトコル／通信鍵の複合区間の期限切れとして観測される。
- Resumeが1006で2回拒否された場合と、4006で1回拒否された場合の新規接続への切り替えを確認した。失敗したResumeの子spanと、最終的にreadyになった復旧の親spanを区別し、開始したspanがすべて終了することを検証した。
- 通知欠落から退出確認付き再入室で回復する既存テストに、失敗した待機と成功した復旧全体を区別する検証を追加した。
- Jaegerへの合成親子spanのOTLP送信・Query API取得・UI表示を確認した。
- `76a28ae`までの変更で`mise run check`が成功した（通常／音声版のテスト・vet、Windows/Linuxビルド）。

## 実Discordでの観測

トレースを有効化した管理再起動では、再生復元の接続が30秒で期限切れになった。ログのtrace IDをJaegerで取得し、Gatewayが約65ms、UDP／プロトコル／通信鍵の複合区間が約24ms、DAVE待機が約29.55秒だったことを照合した。復元spanは`connection_failed`、復旧spanは`stage=dave`・`reason=timeout`で終了している。これは待機箇所の特定であり、DAVE未準備の原因の特定ではない。

利用者がURLなしの`/play`で再開したところ、通知待ち失敗から退出確認付き再入室を経て約5.86秒で接続が回復した。失敗した子spanを保持しつつ、復旧全体は`ready`でErrorを付けず終了していた。

その後のVC往復で、利用者が両方のVCで音声の継続を確認した。各移動の復旧は約280ms／341msで、ログと同じtrace ID・最終結果をJaegerで確認した。

`625717d`の管理再起動では再生復元に成功し、利用者も再起動後の音声を確認した。通知待ち約356ms、通信確立約182ms、音声準備約2.50秒、状態適用から最初の音声送信まで約5.21秒をJaegerで取得した。復元spanは`audio_started`で終了し、準備・Speakingの親子関係、接続トレースとのlink、ログのtrace IDが一致した。Botは管理対象1プロセス・`ready=true`・再生開始済みだった。

## 通知境界と送信経路の補完

`voice.notifications`を追加し、通知が揃った時点で終了してから通信確立を始めることをテストした。通知が不足する期限切れと、通信確立中の明示停止も確認した。後者は通常の中断として扱い、spanをErrorにせず一度だけ終了する。`voice.wait`には`wait_until`を付け、監督処理のready待ちと退出確認待ちを明示した。

`TestVoiceReadyFramesDoNotCreateSpans`は実際の接続管理・送信メソッドへ10,000フレームを渡し、Speakingの1span以外が増えないことを確認する。UDPとDAVEは模擬化している。

同じ経路の`BenchmarkVoiceReadyFrameTracing`をWindows・Go 1.27.2・本番タグで3回ずつ測定した。無効時54.78～55.72ns/op、有効時54.31～55.27ns/opで、どちらも0B/op・0allocs/opだった。この条件では計装有効化による送信経路の負荷増加を観測していない。エンコード、暗号処理、ネットワーク、送信時刻のスケジューリングを含む全体性能の保証ではない。
