# 音声接続確立・復旧の改善計画

## 位置づけと目的

本書は、接続確立の失敗を正しく検出・分類し、復旧と手動再開を一貫して扱うための実装前の計画である。現行実装の基準は `9fc7b3e` とする。[音声接続管理の見直し要件](voice-connection-plan.md)を補足し、今回扱う接続確立・Resume・診断・URLなし `/play` の判断は本書で具体化する。実装済みの挙動は[現行仕様](specification.md)と[アーキテクチャ](architecture.md)を参照する。

今回の障害では、1006切断、Resumeの4006拒否、自動退出・再入室、所属とサーバー通知の受信、接続確立の全体期限切れを確認した。UDP探索、プロトコル送信、鍵応答、DAVE準備のどこで停止したかは未確定である。コードレビューで見つかった故障経路を、当該障害の直接原因と断定しない。

目標は、次の障害で最後に完了した処理と停止した処理を識別でき、失敗済みの接続を `/stop` で破棄しなくても `/play` から再試行できることである。リモート側の内部原因や利用者端末での可聴性まで判定できるとは扱わない。

## 変更範囲と責任

既存の接続世代管理と再生セッションを維持し、まず接続factoryの内部を明示的なハンドシェイク処理へ置き換える。全体の状態機械を一度に再実装しない。

| 担当 | 所有する判断・状態 |
| --- | --- |
| 接続管理 | 所属、通知の収集、最新世代、復旧ID、全体期限、再試行方針、停止・移動の優先 |
| Transport | 一世代のWebSocket・UDP・DAVEとその寿命、接続確立、Resume、送信可能性 |
| 接続試行 | 段階、段階期限、進行記録、成功・失敗・キャンセルの結果 |
| 再生セッション | 現在曲・キュー・再生設定、接続待ち、送信成功後の再生開始、再開要求 |

Transportは確立中から確立後まで同じイベント処理を所有する。接続成功を境に受信先を付け替えない。試行の終了とTransportの終了を区別し、成功済み試行の診断状態を次のResumeや新規試行へ流用しない。

disgoのUDP・暗号化部品は、期限・中断・エラー通知の契約を満たす範囲で再利用する。Readyイベントの処理を委譲してエラーをログだけで終える方式は廃止する。再利用が契約を満たさない場合は、小さな適応層または該当部品の置換を選ぶ。依存ライブラリ全体のfork、MLSや暗号処理の再実装、新しいUDP死活監視、選曲規則、複数Bot対応は対象外とする。

## 状態と結果の契約

通知待ち、接続確立、送信可能、復旧、失敗、終了を区別する。接続確立では、WebSocket接続、Hello待ち、Identify送信・Ready待ち、UDP探索、SelectProtocol送信、SessionDescription待ち、鍵設定、DAVE準備を識別する。名称は実装で調整できるが、失敗が起きた操作を区別できることを条件とする。

通知待ちは必要な所属通知とサーバー通知が揃った時点で完了する。送信可能になるまで通知待ちとして扱わない。受信済みという事実は、消費した通知オブジェクトの有無と別に保持し、世代をまたいで取り違えない。

接続試行の結果は一度だけ確定する。factoryの戻り値、WebSocket切断、段階期限、全体期限、停止要求を同じ終端判定へ合流させる。失敗段階と原因は後始末の前に保存し、遅い成功やキャンセルエラーで上書きしない。旧世代の結果は新世代の状態を変更できない。

確立後のDAVE再交渉は初期接続の段階とは別に扱う。先行・重複イベントは、適用する状態と世代を確認して処理または無視する。新規接続中のResumedなど、進行中のプロトコルと矛盾するイベントは暗黙に別の接続方式へ読み替えず、原因を分類して試行を終了する。無害な未知・重複イベントや現在の段階に関係しない通知は、安全に無視できる条件を定めて記録し、接続を継続する。既存の通知順序・同値トークン・移動の回帰条件を維持する。

参加先として要求したVCと、Discordの所属通知で確認済みのVCを別に保持する。確認済み所属は、所属あり・未所属・未確認を区別する。通知オブジェクトの消費や接続失敗で確認済み所属を失わず、退出確認時に未所属へ更新する。目標VCが設定されていることだけを理由に退出待ちへ進まない。キャッシュとの照合でも所属を確定できない場合は、期限内に確認できなかったことを記録し、参加済み・退出済みのどちらとも断定しない。

## 受信・I/O・DAVEの実行と寿命

WebSocketの受信・デコード・Heartbeat ACK処理を、UDP探索や他のネットワーク待ちで停止させない。UDP探索など接続確立だけに必要なワーカーは試行に属し、DAVEイベント処理と確立後の音声送信はTransportに属する。成功した試行の終了で、継続利用する処理をキャンセルしない。各I/Oには操作の期限を設け、ネットワーク待ちの間は接続管理やTransportの状態ロックを保持しない。DAVEイベントはSessionDescriptionの処理を含めて受信順に直列化し、後続通知が初期化を追い越さないようにする。順序付きキューは有限とし、溢れた場合はイベントを黙って捨てず、当該接続を失敗扱いにする。

contextのキャンセルだけをI/O終了の証拠にしない。disgoのUDP探索は固定I/O期限とロックを使い、Closeも同じロックを待つため、単にgoroutineで包む、または同じUDPラッパーのCloseを別goroutineから呼ぶだけでは即時中断を保証できない。実ソケットの中断と期限を制御できる境界を設け、ロック待ちを含めて検証する。

停止・世代交代時は先に送信を無効化し、実I/Oを中断してから資源を解放する。新しい接続の進行を旧接続の後始末で止めず、後始末完了を追跡する。期限付きで待つ側が返っただけで、ワーカーやソケットが解放されたとは扱わない。終了待ちの上限と超過時の診断を実装・テストで明示し、無制限の後始末goroutineを残さない。

DAVEの送信コールバックもTransportの寿命に従わせ、失効世代・解放後の呼び出しを拒否する。依存側の内部再試行と接続管理の再試行を重ねない。送信失敗後に依存側の状態整合性と再試行の終了を保証できない場合は、初期確立中なら試行を失敗させ、確立後なら接続管理へ復旧判断を通知する。失効した旧世代の失敗は新世代の復旧を起動しない。継続可能と分類するには、使用する依存版の再試行条件・状態の巻き戻し・キャンセルを確認し、失敗注入で裏付ける。エラー文字列を変えるだけで回復を保証したとは扱わない。

新規接続・VC移動では新しいDAVEを用意し、Resumeでは既存DAVEとUDPを維持する。SSRCとOpus codecの対応付けなど、依存が担っていた副作用を移行時に確認する。DAVEの解放はTransportの所有資源として追跡し、コールバックをキーにした登録との不一致で解放漏れを起こさない。準備完了判定は既存のプロトコル0対応を維持し、epoch成立だけを待つAPIへ単純置換しない。

## 期限と復旧方針

全体30秒、Resume最大2回・各5秒、参加・退出要求送信の最大3回、退出確認付き再入室は一復旧で最大1回、自動再入室は直近5分で2回という既存の上限を維持する。明示的な再開は新しい復旧予算とする。段階期限は全体の残り時間を超えず、重複通知・内部再試行・復旧中の再移動で全体期限を延長しない。

Resumeの各5秒は、Resume試行の開始からResumed受信までを指す。Resumed受信後のDAVE準備は全体の残り予算で待ち、Resumeの再試行回数に戻らない。

初回参加と再入室の双方で、通知待ちと退出確認はそれぞれ最大5秒とする。接続確立内部の期限は操作ごとに明示し、残り時間が少ない場合の中断をテストする。数値を変更する場合は実測または失敗注入の根拠を記録する。タイマーとログは同じ段階状態を参照する。

再入室の通知待ちを全体残り時間から最大5秒へ制限する点は、現行実装からの変更である。WS接続・送信・UDP探索など個別I/Oの上限は依存の既存値を起点に決め、Hello/Ready・SessionDescriptionの待ちと区別して実装時に一覧化する。DAVE準備は対向や参加者との交渉を含むため、初期方針では全体の残り予算まで許容する。独立した短い上限を導入する場合は検証根拠を必要とする。キュー容量・解放待ち上限を含む具体値は、対応する実装単位で根拠と境界テストを記録して確定する。

| 事象 | 判断 |
| --- | --- |
| 一時切断 | 既存のコード分類に従ってResumeを試す |
| Resumeのセッション失効拒否 | 新しい接続情報を取得して新規接続する |
| Resume成立後のDAVE未準備 | 二度目のResumeを送らず、残り予算内でDAVEを待つ |
| 通知不足 | 権限・所属を確認し、既存の退出確認付き再入室を一度だけ行う |
| 通知受信後の接続確立失敗 | 段階と原因を返し、今回の実装では同じ資格情報による無条件再試行や追加の再入室を行わず保持停止する |
| 停止・外部退出・再接続禁止の拒否 | 復旧を中止し、自動で参加し直さない |

最終失敗後は追加の自動退出を行わず、既存の無人退出・待機退出設定を適用する。失敗済みでVC所属が残っている状態からURLなし `/play` で再開する場合は、最新の権限・所属を確認して退出確認付き再入室から開始する。この退出も新しい明示的試行の再入室上限に含める。所属が解除済みなら通常の参加から開始する。古い接続の後始末が新しい所属への退出要求を送らないことを条件とする。

## 再生とコマンド応答

URLなし `/play` の結果を、既に再生中、再生準備中、復旧中、再開要求受付、再生対象なし、失敗に分ける。接続が送信可能でも音源取得中なら再生準備中とし、連打で二重に接続や再生を起動しない。失敗直後の再開では、古い音源・候補取得をキャンセルし、現在曲の保持と旧ループの終了を確認してから一度だけ新しいループを開始する。実行中フラグだけで終了を判定せず、復元処理を含む旧ループの後始末と新ループの初期化が競合しないようにする。終了待ちはロック外で期限付きとし、完了しなければ再開を失敗として扱う。Discordへの通知完了を再生処理の終了条件にしない。

再生要求の失効とVC移動を分ける。受付確定前にVCが変わった要求は最新の権限・所属で再判定し、対象が変わっていれば拒否する。受付済みの再生は、接続確立中も最新VCへの移動に追従する。停止や対象選曲の変更で失効した要求は後から再生を開始できないが、移動だけで受付済みの再生を取り消さない。接続世代・再生要求・応答先の寿命を区別し、旧VC向けの通知が移動後の再生を取り消さないようにする。キュー消去を再生停止と同一視せず、既存の消去範囲に従って対象選曲が失効したかを判定する。

応答は受付と結果を分ける。「再開しました」は最初の音声Write成功後に限り、準備中は準備中と表示する。接続の30秒期限へ音源取得・Mix候補取得の時間を含めない。結果を待つ通知処理は要求の寿命に結び付け、停止・失敗・要求失効で終了する。Discordの応答更新ができなくなっても再生を止めず、通知失敗を記録する。音源取得失敗で次曲へ進んだ場合は、その実際の送信開始を再開結果とし、音源の失敗を接続失敗へ変換しない。

接続完了を待つ前に受付応答を返し、最終結果で元の「準備中」応答を更新する。送信開始前に全曲取得失敗・連続失敗上限へ到達した場合は音源の失敗、対象がなくなった場合は再生対象なし、停止・要求失効時は中止として完了させる。移動で応答先が失効した場合も、その応答を中止または移動に伴う終了として閉じ、移動先の曲情報を旧応答へ書き込まない。応答更新不能の場合を除き、「準備中」を残したまま通知処理だけを終了しない。

URLあり `/play`、`/playnext`、Mix等の曲追加は、自動復旧中・初回接続中・失敗後の再接続中も既存の権限・上限に従って受け付ける。接続中という理由だけで追加を拒否する現行仕様を変更し、キューへの追加と接続の起動を分離する。追加ごとに最新の所属を確認し、既存の接続試行を共有して二重起動を防ぐ。曲の追加成功と音声接続の状態を分けて案内する。キュー順序、音量、自動再生、履歴、管理保存、保持曲の再開規則は変更しない。アイドル時に失敗した接続を、存在しない現在曲の保持として扱わない。

## 障害記録

Jaegerの有無にかかわらず、失敗の要約をJSONログに残す。復旧ID、試行ID、世代、開始契機、最後の完了段階、実行中段階、段階所要時間、期限種別、受信済み通知、原因分類、次の判断を記録する。DEBUGではイベント順序、Heartbeat ACKの経過時間、各I/O結果、DAVEの安全な準備状態・統計、キャンセル元、後始末の結果を追えるようにする。

制御・ログ・トレースは同じ進行記録を使用する。完了済み試行の参照を現在試行として残さず、Resumeの診断も独立した寿命を持たせる。出力順が非同期で前後しても観測時刻と識別子で照合できることを条件とする。記録経路は有限バッファとし、溢れを集約し、属性の並びに依存する型アサーションでpanicしないようにする。

トークン、セッションID、暗号鍵、MLS本文、生のGatewayペイロードは記録しない。DAVE診断には依存ライブラリの安全な状態・統計を利用し、MLSを独自解析しない。[ログ設計](logging-plan.md)の秘匿・レベル・出力責任を維持する。計測先の停止や遅延を音声接続失敗の原因にしない。

## 検証と完了条件

| 対象 | 必須の検証 |
| --- | --- |
| 段階別失敗 | WS接続、Hello/Ready、UDP探索、SelectProtocol、鍵応答・設定、DAVEの失敗とタイムアウトを注入し、正しい段階で終了する |
| 今回の故障経路 | 1006→Resume4006→再入室→通知受信→各段階で停滞。保持停止後の `/play` で新しい試行が開始する |
| Resume | Resume成立後のDAVE遅延、Resume失敗後のrun解放、Speaking再通知、二重Resume防止 |
| 競合と順序 | 全段階でstop・移動・外部退出、旧世代の遅延成功、通知逆順・重複、DAVE通知の先行、キュー溢れ |
| 実I/Oと解放 | UDP探索中のキャンセル、残り期限が短い場合、遅いDAVEコールバック、I/Oとワーカーの終了、資源の残留がないこと |
| 手動再開 | 復旧中、期限の直前・直後、古いループ終了前・後、連打、再開待ち中の停止、空キュー、音源取得失敗 |
| 所属と受付 | 初回の所属通知未着、退出確認後の再参加失敗、未所属からの再開、各接続段階での追加受付と二重起動防止 |
| 要求と応答 | 受付前後の移動、停止・キュー消去との競合、全曲取得失敗、準備中の再コマンド、応答更新失敗でも再生が継続すること |
| 計測 | Jaegerなし・ログ出力遅延・バッファ溢れでも制御が進み、秘密を含まない要約が得られる |

自動テストは実ネットワーク障害待ちにせず、ローカルWS・UDPと制御可能な時計・同期点を利用する。テストの都合で本番の状態や期限判定を別実装にしない。関連テスト、race検査、Windows/Linuxビルドを通し、実Discordで再生・VC往復・停止後の再開を確認する。実機確認と失敗注入の結果は区別して記録する。

実装は、接続確立と診断、復旧判断と再開応答、統合検証の単位でレビュー・コミットする。各単位で現行仕様・アーキテクチャ・運用手順の該当箇所を更新する。反映には既存の曲境界での管理再起動を使う。停止箇所を分類できること、停止後に復活しないこと、失敗後に曲を失わず明示的に再開できることを完了条件とする。

## 判断の根拠

- [discord.js Networking](https://github.com/discordjs/discord.js/blob/main/packages/voice/src/networking/Networking.ts)：WS・UDP探索・プロトコル選択・Ready・Resumeの段階と資源の所有。状態区分を参考にし、DAVE準備完了の条件は本Botの要件を維持する。
- [discord.py VoiceConnectionState](https://github.com/Rapptz/discord.py/blob/master/discord/voice_state.py)：通知収集、接続フロー、期限、退出確認と復旧の区別。
- 現行依存 `disgo v0.19.6` の `voice/conn.go`・`voice/udp_conn.go`：イベント委譲でのエラー通知不足、固定I/O期限とCloseのロック待ち。
- `dave-go v0.5.1` とアプリのDAVEラッパー：コールバック、内部再試行、プロトコル0の準備判定と解放。

GPT-6 Astra（中）とGemini 4 Argon（High）の独立レビューを反映した。レビュー所見は設計上のリスクとして採用し、障害原因の実証やテスト成功の代わりには扱わない。公開ソースのリンクは可変であり、実装時に参照した版と検証結果を記録する。
