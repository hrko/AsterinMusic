# gopus SIMDへの移行とキュー保持

> 検証・移行時点の記録です。現在の動作は[現行仕様](specification.md)、構成は[アーキテクチャ](architecture.md)、操作は[開発・運用手順](development.md)を参照してください。

2026-11-02。ライブ用`opus`ビルドのエンコーダーをlibopusから、比較検証済みのgopus `v0.2.3-0.20261023192543-88e87250952e`へ変更した。miseの`serve`・`build-voice`はGo 1.27.2、GOEXPERIMENT=simd、GOAMD64=v3でビルドする。Opus経路のCGO依存はなくなったが、DAVEのCGO依存とFFmpegの入力デコードは残る。

設定は48kHzステレオ、20ms、96kbps、complexity 9、CVBR。送信直前の音量適用、10msランプ、曲単位のエンコーダー状態、終了時のlookahead分のゼロ埋め、遅延後の連続送信防止を維持した。

手動追加キューは変更ごとにJSONへ保存する。追加者・曲情報・エントリーID・追加日時・プレイリスト情報・追加者ごとの順番・公平な巡回順・再生中の手動追加曲を保持する。再起動後、再生中だった曲を待機列の先頭へ戻し、URLなしの`/play`で先頭から再開する。再生位置、音量設定、自動再生状態、ボタン、音声接続は保存しない。

既定の保存先はGit管理外の`.dev/state`。ファイル名にアプリIDとサーバーIDを含める。`RAINMUSIC_STATE_DIR`で変更可能。同一保存先は1プロセスだけで使用する。一時ファイルへ書き込み・Sync後に置換し、読めない・破損した状態は起動時にエラーとする。電源断や保存失敗時の完全な耐久性は保証しない。保存失敗はログに記録し、追加・消去操作にも警告を返す。

検証結果：

- Windows `mise run check`成功。標準構成とgopus SIMD構成のLinux/Windowsクロスビルドを含む。
- Windows `mise run native-audio-check`成功。CGO無効で実行。251フレームのペーシング試験は遅延0件。音量設定から次パケットまで20.03ms、復号後ミュート40ms以内、復帰80ms以内。キャンセル試験も成功。
- WSL Linux `go test -race -tags opus ./...`（GOEXPERIMENT=simd、GOAMD64=v3）成功。
- キューの再起動復元、追加者・メタデータ・公平な順番、再生済み曲の除去、満杯時の中断曲復元、消去、破損ファイル、保存失敗をテスト。終了時の中断曲保持と明示的なstopの消費を区別するセッションテストも成功。
- Windows DAVE対応Botのビルド・Discord接続成功。実際のDiscord上での今回の版の試聴は未実施。

起動時の復元件数は0曲だった。保存機能のない旧版のメモリ内キューを抽出して移す処理は行っていない。
