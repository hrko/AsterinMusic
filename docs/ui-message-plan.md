# Botメッセージの変更案

本書は[UI設計指針](ui-guidelines.md)の適用計画。コマンド応答・公開範囲・取り込みボタンの変更は実装済み。毎曲の準備通知の停止と連続失敗通知の集約も実装済み。現在の挙動は[現行仕様](specification.md)を参照する。

## コマンド応答

| 操作 | 変更案 | 公開範囲 |
| --- | --- | --- |
| 単曲追加 | 「キューに追加しました」のEmbedに共通の曲情報。既存のサムネイルを利用 | 公開 |
| playnext | 「自分の次の番に追加しました」。割り込みによる即時再生や全体の次曲とは表現しない | 公開 |
| プレイリスト追加 | 「N曲を追加しました」。取得済みならリスト名リンク、なければ一般的なリストリンク。全曲を列挙しない | 公開 |
| Mix追加 | 「MixからN曲を追加しました」。起点曲リンクと操作したユーザー。通常の除外集計は表示しない | 公開 |
| URLなしplay | 「キューを再開しました。」 | 公開 |
| stop / skip | 短い成功応答を維持。停止時は待機キュー保持を補足 | 公開 |
| queue edit | 本人専用の一覧で選択・移動・削除。結果も同じ画面で表示 | 本人限定 |
| queue clear | 待機曲数を示す確認画面から確定・キャンセル。再生中の曲と自動再生設定の維持を補足 | 本人限定 |
| volume表示 | 「音量：N%」。毎回の初期値・100%の説明は省略 | 本人限定 |
| volume変更 | 「音量をN%に変更しました。」。0%はミュートを明示 | 公開 |
| autoplay on/off | 短い成功応答。起点待ちや現在曲の継続など、その操作の結果だけ補足 | 公開 |
| autoplay status | ON/OFF、起点曲、待機状態のEmbed。一般的な動作説明は省略 | 本人限定 |
| queue | 現在のEmbedを基にBot名の繰り返しを除去。候補である説明・不明時間は維持 | 本人限定 |
| nowplaying | 共通の曲情報を維持し、経過時間は表示時点と明記 | 本人限定 |

単曲画面の曲名の省略上限はキューと分離する。具体的な上限はモバイル幅と長い曲名の表示確認で決める。リスト名取得のための新しいAPI呼び出しは追加しない。

## 取り込みボタン

付属リストの案内は「付属のプレイリストも追加できます」または「付属のMixから最大20曲を追加できます」とする。本人限定・15分の期限は操作前の補助情報として残す。MixがYouTube画面と一致しない可能性は操作前に短く案内し、詳細は文書へ置く。

取り込み中は元のメッセージを更新してボタンを無効化する。完了時は結果を表示してボタンを削除する。追加済みの最初の曲は維持されるため、見出しを「付属リストからN曲を追加しました」として元の単曲追加と区別する。0曲追加の場合は成功見出しを出さず、「追加できる曲がありませんでした」または取得失敗として実際の状態を示す。部分成功は追加済み範囲を維持し、重複追加を招く再試行を提示しない。

## 自動通知

毎曲の「再生準備」通知は送信しない。今回、曲変更通知の設定追加は行わない。再生開始の確認にはnowplaying・queue・アクティビティを使う。

単発の取得・再生失敗は曲名リンクと「次の曲へ進みます」を短く表示する。連続失敗は同じ通知を更新し、通常キューの停止、自動再生OFF、候補取得失敗によるOFFは最終状態を1回通知する。状態変化を隠さず、同一原因の詳細を繰り返さない。ニコニコ認証の修復は管理者向けの短い案内を添える。

## エラーと部分成功

操作前の入力・権限エラーは本人限定。処理開始後の部分成功は公開の結果メッセージで知らせる。公開の処理中応答を開始した後に完全失敗した場合は、その元の応答を失敗へ更新する案とする。公開範囲を途中で変更できる前提では設計しない。

追加に成功したが音声接続に失敗した場合は、黄色の「N曲を追加しました」に「音声に接続できませんでした。キューは保持しています」と続ける。追加そのものに失敗した場合は赤色の「追加できませんでした」とする。保存失敗は再起動時の消失リスクを本文に示し、ログ確認を求める。

## 適用順序と確認

1. 曲情報、成功・部分成功・失敗の共通表示を用意し、追加結果と取り込みボタンを整理する。
2. 状態確認の公開範囲と表示を統一する。本人限定でも操作権限は従来どおり判定する。
3. 再生準備通知を削除し、連続障害の通知を整理する。

通常成功・0曲・部分成功・取得失敗・接続失敗・保存失敗を確認する。長い曲名、欠落メタデータ、手動曲と自動曲、ボタンの期限切れ・他人操作、メッセージ更新時の古いEmbedやボタンの残存を検証する。実装時に現行仕様と各詳細文書を更新する。

## 合意と適用状況

- nowplaying、volumeの表示、autoplay statusを本人限定にする。
- 毎曲の再生準備通知を停止し、今回は通知設定を追加しない。
- 連続失敗を同じ通知に集約する場合の区切りを決める。成功した曲の最初の音声パケットの送信成功でリセットする。

上記3点は利用者の合意済み。専用の再生ログチャンネルへ再生曲だけを投稿する任意機能を将来の要件として保持する。チャット履歴から曲を振り返る用途を想定し、今回の実装では設定・投稿処理を追加しない。
