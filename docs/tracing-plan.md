# OpenTelemetryトレース計装の方針

実装状況：設定・SDK初期化／終了・OTLP/HTTP出力・slogの関連付け基盤を導入中。接続・復元の計装、閲覧環境、総合検証は未完了。本書の完了条件はそのまま維持する。

## 目的と位置付け

本書は未実装の導入方針である。音声接続・復旧で、どの段階に時間を使い、どの試行が失敗し、最終的に何をしたかを追跡できるようにする。[ログ設計](logging-plan.md)と[音声接続管理](voice-connection-plan.md)の責務分離・秘匿・期限・世代管理を維持する。計装を理由に再試行回数や復旧期限を変更しない。

現状は構造化ログと処理IDで結果を追えるが、接続確立中の待機を十分に区別できない。接続管理が期限切れで世代を無効化すると、非同期の接続処理が返した詳細な失敗段階を結果へ反映できない経路もある。計装時には、観測した段階を試行ごとに保持し、期限切れと競合しても診断結果を残す。これを接続失敗自体の修正と混同しない。

トレースは処理間の関係と時間、ログは出来事と最終対応を担当する。トレースが無効、未送信、破棄された場合にも、既存ログから復旧結果とキューの扱いを確認できること。再生履歴DB、利用者向け通知、将来の再生ログチャンネルは別機能とする。

## 初回の範囲

初回はGoのOpenTelemetry API・SDKによる手動計装、OTLP出力、slogとの関連付け、ローカルでの閲覧検証を対象にする。計装対象は以下に限定する。

| 対象 | 計測する区間・結果 |
| --- | --- |
| 初回接続・VC移動・通信断復旧 | 要求または障害検知から、最新世代が送信可能になるか、失敗・中断が確定するまで |
| 各接続試行 | 通知待ち、Resume、Gateway接続、UDP検出・プロトコル選択、通信暗号鍵待ち、DAVE準備、必要なSpeaking通知 |
| 退出確認付き再入室 | 権限確認、退出要求・確認待ち、再参加要求・通知待ち。実際に実行した区間のみ |
| 管理再起動後の再生復元 | 復元対象ごとに、状態適用から接続・音声準備・最初の送信成功、または失敗・中断まで |

接続のreadyと実際の音声送信開始は区別する。停止状態の復元は状態適用で完了し、再生開始を待たない。復元時の音声準備は最初は一つの区間でよく、yt-dlp等の詳細計装を必須にしない。

通常の曲の準備、メタデータ補完、Discord応答・通知、保存処理への拡張は後続とする。全コマンド・全HTTP通信の自動計装、メトリクス・OTelログへの移行、常設の収集基盤、tail samplingは初回に含めない。20msごとのフレーム、Heartbeat成功、DAVEのポーリングごとにspanやeventを作らない。

## spanの境界と非同期処理

spanは開始・終了を持つ処理区間とする。接続管理が一連の接続・復旧の親spanを所有し、試行と待機区間を子spanにする。親の結果と個別試行の結果を分け、再試行で回復した親を失敗扱いにしない。通知の採否や世代交代など、期間を持たない出来事は有限個のeventとする。

span名は`voice.recovery`、`voice.connect`、`voice.resume`、`playback.restore`など固定の分類とし、ID・URL・曲名を埋め込まない。プロセス全体や長時間の再生セッションを一つのspanにしない。接続世代、試行番号、復旧単位を区別し、旧世代の遅延完了で新世代のspanを書き換えない。

同じ処理に属する呼出しにはspanを含む`context.Context`を渡す。操作完了後も独立して動く復旧などは、その処理の所有者が管理するContextで新しいトレースを開始し、起因する処理のSpanContextがあればlinkで関連付ける。コマンドのキャンセルを長時間の再生へ引き継いだり、関連付けのために既存の期限・キャンセルを外したりしない。GoのContextによる親子関係と、非同期の因果関係を表すlinkは公式APIに従う。[Go計装](https://opentelemetry.io/docs/languages/go/instrumentation/)、[span link](https://opentelemetry.io/docs/concepts/signals/traces/)

Contextは呼出し引数を基本とし、接続全体に「現在のspan」を一つだけ置かない。コールバックへの受け渡しは試行・世代にひも付け、終了時に参照を解放する。spanは成功、失敗、停止、世代交代の各経路で一度だけ終了する。終了後のspanへの追記に依存しない。

UDP検出など依存ライブラリ内部の区間は、公開された境界やコールバックで確認できる範囲だけを計測する。Gateway接続完了をUDPや鍵の準備完了とみなさない。内部の区間を分離できない場合は複合区間であることと最後に確認できた段階を記録し、観測していない所要時間を推定で埋めない。計装だけを目的とする依存ライブラリのforkは初回に導入しない。

## 結果・属性・ログの関連付け

正常終了ではspan statusをUnsetのままとし、失敗した処理はErrorと安全な`error.type`を付ける。明示停止・スキップ・旧世代の破棄は通常の中断として理由を記録する。期限切れは待機段階と期限の種類（試行／復旧全体）を区別する。再試行が成功した場合、失敗した子spanには失敗を残し、親には最終結果を記録する。[エラー記録の指針](https://opentelemetry.io/docs/specs/semconv/general/recording-errors/)

`RecordError`への生エラー投入は行わない。外部エラーに含まれるURL・トークン等を避け、安全な分類に変換する。span statusの説明、event、resource、SDK自身のエラー出力にも同じ秘匿規則を適用する。

| 分類 | 記録方針 |
| --- | --- |
| resource | `service.name=asterinmusic`、ビルドバージョン、起動ごとの非認証用インスタンスID。ホスト名・ユーザー名等を無条件に収集しない |
| 関連付け | Bot・サーバー・VC・再生・操作・復旧ID、世代、試行番号。既存ログと意味・型を合わせる |
| 診断 | 開始契機、段階、結果、理由、残り期限、切断コード、HTTPステータス、キュー保持の判定など必要な項目 |
| 記録しないもの | 認証情報、暗号鍵、認証用セッションID、曲名、入力URL、自由入力、ユーザー名、通信本文、コマンド引数・標準エラー原文 |

独自属性は`asterinmusic.*`にまとめ、標準属性は意味が一致する場合だけ使用する。識別子はspan属性とし、span名やresourceにサーバー・曲ごとの値を追加しない。属性数・値長・event数・link数には上限を設ける。高頻度の重複通知は件数を集約し、開始・終了・最終失敗の情報を優先する。

既存の注入された`*slog.Logger`を維持する。共通HandlerでログのContextから有効なSpanContextを読み、`trace_id`、`span_id`、`trace_sampled`を付ける。Contextにspanがなければ省略し、架空のIDを生成しない。長寿命ロガーの`With`へtrace IDを固定しない。未サンプリングのIDがログにあっても、閲覧基盤にトレースが存在する保証はない。

ログレベルとトレースの有効化は独立させる。既存の属性フィルター、依存ログの秘匿、`WithGroup`の挙動を維持し、SDKやexporterのエラー出力から再帰的な計装・ログ出力を起こさない。ログとトレースに共通する分類は再利用するが、既存のログをすべてspan eventへ複製しない。

## 初期化・設定・送信

SDK・exporter・resourceの生成と終了は起動層へ集約する。処理層には標準のTracerまたはTracerProviderを注入し、未設定時はno-opを使用する。初回から独自の汎用トレーシングインターフェースを作らず、SDK設定と秘匿・分類の補助を小さな内部パッケージへ分離する。テストでグローバルProviderの差し替えを必要としない構成とする。

設定省略時は無効とし、外部へ送信しない。初回はOTLP/HTTPに絞り、有効化、送信先、必要な認証ヘッダーを既存の設定ロード・変数展開で指定できるようにする。対応キー、URLの形式、環境変数との優先順位は実装時に設定仕様へ明記する。SDKが暗黙に読む`OTEL_*`を含め、意図しない送信先やヘッダーが優先されないことを検証する。Discord・YouTube等へtraceヘッダーやbaggageを送信する機能は追加しない。

有効化時の構文・値の不正は起動前検証で拒否する。収集先の停止・通信失敗はBot起動や再生継続の条件にしない。遠隔送信はTLSを基本とし、ローカルHTTPは明示設定で許可する。送信先URL・ヘッダーをログへ丸ごと出さない。

送信には有界のBatchSpanProcessorを使い、キューが満杯なら計装データを破棄する。`WithBlocking`は使用しない。送信の待ち時間・再試行・保持量に上限を設け、状態ロック内や音声フレーム経路で通信・flushを行わない。[Go SDKのBatchSpanProcessor](https://pkg.go.dev/go.opentelemetry.io/otel/sdk/trace#BatchSpanProcessor)

終了時は再生状態の保存と音声接続の終了を優先し、残った処理のspanを終了した後、独立した短い期限付きContextでProviderをshutdownする。送信完了を無期限に待たず、管理再起動の猶予内に収める。強制終了時や送信先障害時にはトレースを失う場合があり、永続キューや完全配信は保証しない。

初回は対象範囲を限定したうえで有効時に全件サンプリングする。ただしバッファ満杯・送信失敗による欠落はあり得る。将来、割合を下げる場合は、head samplingでは失敗したトレースの全件保持を保証できないことを明記する。tail samplingの必要性は量と運用負担を見て別途判断する。[サンプリングの比較](https://opentelemetry.io/docs/concepts/sampling/)

## 閲覧環境と実装時の決定事項

保存・検索・表示はOTLP対応の外部バックエンドが担当する。Collectorを必須にせず、初回の検証ではローカルでトレースを閲覧できる構成を一つ用意する。具体的なバックエンドと固定バージョンは実装時に選定し、起動・停止・閲覧・削除の手順を開発手順へ記載する。開発依存はmise、必要な自動化はGoとする。通常のBot起動に閲覧環境の起動を必須としない。

IDを含む診断情報は運用者向けデータとして扱い、保存先の閲覧制限、保持期間、削除方法を明記する。検証データはGit管理外に置き、外部サービスへの自動アップロードは既定にしない。

SDKの固定バージョン、バッファ・属性等の上限、送信・終了期限、設定キーは実装時に確定し、テストと現行文書に残す。これらの値を選ぶ際も、再生処理の期限・挙動・認可・プライバシーを変更しない。

## 検証と完了条件

| 検証 | 確認すること |
| --- | --- |
| 通常接続・復元 | 親子関係、世代・試行の区別、readyと最初の送信成功の区別、停止状態の復元 |
| 障害注入 | 通知欠落、Gateway拒否、UDP／鍵／DAVE待機、Resume拒否、再入室、全体期限切れの段階と結果 |
| 競合・終了 | VC往復・連続移動、遅延した旧世代、明示停止、キャンセルとタイムアウトの競合。spanの終了漏れ・二重終了・他世代への混入がない |
| ログ照合 | 同じ処理のtrace/span IDが一致し、無効・未サンプリング時にも既存ログで結果を追える |
| 秘匿 | 合成秘密情報を外部エラー・URL・ヘッダーへ入れても、属性・event・status・resource・SDK診断ログへ漏れない |
| 送信障害・負荷 | 収集先停止、遅延、満杯、終了時タイムアウトで再生・保存を妨げず、メモリ・goroutineが無制限に増えない |
| 有効／無効の比較 | 音声送信遅延、CPU・割当量を比較し、フレーム単位の計装や再生品質の悪化がない |

自動テストはインメモリのspan記録と制御可能な通信先を使い、公開サービスへ接続しなくても実行できること。ローカル閲覧環境では実際のOTLP送信とログからの照合を確認する。既存チェック・Windows/Linuxビルドを通し、実Discordで再生復元とVC往復を確認する。意図的な障害は模擬環境で検証し、実機で確認していない経路を区別して記録する。

導入完了時に、実装した範囲・設定・既知の観測限界を仕様書、アーキテクチャ、開発手順へ反映する。詳細段階が観測できないまま、その段階まで計装済みとは扱わない。
