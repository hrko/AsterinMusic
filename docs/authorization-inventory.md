# 認可導入前の操作棚卸し

本書は[導入方針](authorization-plan.md)の第一段階として、現在の実装と認可を適用する入口を記録する。以下の操作IDは導入用の候補であり、現行の設定キーではない。

## 操作と入口

| 操作ID候補 | 入口 | 現在の条件 |
|---|---|---|
| help.view | `/help`、候補検索、ガイド・詳細メニュー | 設定サーバー。画面操作は本人・有効期限・起動世代も確認 |
| queue.add | URL付き`/play`、`/mix`、付属リスト・Mixボタン | VC参加、接続中ならBotと同じVC。取得後の追加時にも確認 |
| queue.add_next | `/playnext`、その付属リスト・Mixボタン | queue.addと同じ。本人キュー内の挿入位置も検証 |
| playback.resume | URLなし`/play` | VC参加、接続中ならBotと同じVC |
| playback.stop | `/stop` | 同上 |
| playback.skip | `/skip` | 同上 |
| queue.clear | `/queue action:clear` | 同上 |
| queue.view | `/queue`、前後ページ・更新ボタン | 設定サーバー。ボタンは本人。VC参加条件なし |
| playback.view | `/nowplaying` | 設定サーバー。VC参加条件なし |
| volume.view | 引数なし`/volume` | 設定サーバー。VC参加条件なし |
| volume.set | 数値付き`/volume` | VC参加、接続中ならBotと同じVC |
| autoplay.view | `/autoplay status` | 設定サーバー。VC参加条件なし |
| autoplay.set | `/autoplay on/off` | VC参加、接続中ならBotと同じVC |
| history.view | `/history`、ページ操作・ページ入力モーダル・選択 | 参加中VCの履歴。画面操作は本人・VC・メッセージ・版・有効期限も確認 |
| history.readd | 履歴から通常位置へ追加 | 履歴画面の条件とqueue.addの条件 |
| history.readd_next | 履歴から本人の次の番へ追加 | 履歴画面の条件とqueue.add_nextの条件 |

履歴からの再追加は、履歴を読めるだけでは許可しない。追加先の操作も許可されていることを要求する。付属リストは元の曲を追加できた事実だけで許可せず、ボタン操作時点で改めて評価する。

## 固定条件とポリシー条件の境界

本人専用画面の所有者、有効期限、起動世代、操作対象の存在、キュー世代、挿入位置の整合性は固定条件として残す。入力検証や再生処理の排他制御も認可へ移さない。

操作の許可はサーバー内の利用者・ロール・管理者属性、対象Bot・VC・セッション、必要なら曲の追加者を使って評価する。Discordの閲覧制限を満たすことは追加ポリシーでも解除できない。認可時の属性はDiscordから取得した事実を使い、ボタンIDや入力URLに含まれる申告値を信用しない。

現状のキュー・再生情報の閲覧には対象VCの閲覧権限確認がない。導入時には非公開VCの情報が漏れないことを独立して検証する。VCへの参加必須化と、Discord上でそのVCを閲覧できることの確認は別の条件として扱い、閲覧できる利用者の既存操作を不用意に制限しない。

## 再確認が必要な境界

- 外部サイトの取得後、キューに反映する直前：利用者の現在のVC・ロール、対象VC、操作世代を再確認する。
- 履歴DBの読み込み後、表示する直前：対象履歴の閲覧条件と画面の有効性を再確認する。
- ボタン・モーダル送信時：最初のコマンドと同じ操作の認可に加え、画面固有の固定条件を確認する。
- ロック待ち・保存待ちの後：許可判定と実際の変更対象が食い違わないよう、対象世代と状態を照合する。

現在の`session.authorize`はVC条件のみを扱い、ロールの再確認は行っていない。新しい認可をコマンド入口に一度だけ加える方法では、外部取得中のロール変更に対応できない。

## 次の検証で確定する事項

共同操作の既定は現在の操作範囲を基本とする。DJ方式では一般参加者の曲追加・閲覧と、DJの共有状態変更を分ける。再開、本人の曲のスキップ、管理者・所有者の許可、DJロール未設定時の扱いは、Cedarの評価試験とともに許可表へ定める。

同じVCという条件のカスタマイズ範囲、停止中のキューに結び付く閲覧対象VC、ロール・チャンネル権限を最新化する方法も本体導入前に確定する。まだ評価エンジンやBotの挙動は変更していない。

実装上の確認箇所：`internal/discordbot/commands.go`、`handlers.go`、`session.go`、`autoplay.go`、`mix.go`、`history_view.go`、`queue_view.go`、`help.go`。
