# Agyによる外部モデルレビュー

Antigravity CLI (`agy`) に独立レビューを依頼し、既存会話で相互確認を行う手順。2026-11-03にWindowsのCLI 1.4.12で確認した。アカウントやバージョンにより利用できるモデル・承認モードは異なる。

## 起動と依頼

リポジトリのルートを作業ディレクトリにする。利用可能な機能とモデルは次で確認する。

```text
agy --help
agy models
```

短い接続確認は非対話形式で実行できる。

```text
agy --model gemini-3.8-flash-low --output-format json --print-timeout 60s -p "接続確認です。ツールを使わず AGY_GEMINI_OK とだけ返してください。"
```

レビューは、個別承認を操作できる対話形式を基本とする。

```text
agy --model gemini-4-argon-medium -i "レビュー依頼文"
agy --model gemini-4-argon-medium --conversation CONVERSATION_ID
```

依頼文にはプロジェクトの目的、レビュー観点、文書の入口（AGENTS.md、docs/index.md）、結果の形式を伝える。独立レビューでは他モデルの所見を渡さず、相互確認の段階で渡す。細かな調査順序を指定する必要はない。

読み取りレビューでは、ファイル変更・コミット・Bot操作・外部サービスアクセス・秘密ファイルの読み取り・追加エージェントの使用を禁止すると明示する。結果には根拠ファイルと行番号、影響、改善方向、未確認事項を求める。モデルの「確認済み」という表現だけで実行検証済みと判断しない。

## 承認と実行環境

`--mode` は `plan`、`auto`、`accept-edits` を受け付ける。ただし確認時のアカウントでは `auto` が利用できず、警告とともに既定の `request-review` へ戻った。指定した値だけでなく、警告と実際のモードを確認する。Autoは読み取り専用の強制機構ではない。

非対話実行ではコマンドが承認待ちにならず、`denied_actions` を返してターンが終了する場合がある。JSONの `status: SUCCESS` や終了コード0だけではレビュー完了を意味しない。最終報告の有無と拒否された操作を確認する。

対話実行をエージェントから操作する場合はPTYを使い、返された実行セッションIDを保持する。承認画面で対象を確認し、読み取りに必要な操作だけを今回限りで承認する。恒久許可・会話全体の許可・`--dangerously-skip-permissions` はこの手順では使わない。

初回のフォルダー信頼確認は、読み取りだけでなく編集・実行を含むため、個別の読み取り承認と区別する。今回の運用では利用者の明示許可を得てから進めた。実行環境側の承認審査に拒否された場合は迂回せず、理由と必要な許可を説明する。

制限環境ではWindowsの認証ストレージやCLIログ保存先へアクセスできず、ログイン済みでも未認証と表示された。再ログインを促す前に実行環境の制限を確認する。今回の検証はホスト側での実行により既存認証を利用できた。

依存ライブラリの実装を読む場合、このプロジェクトのモジュールキャッシュは `.dev/go-mod`。標準の `~/go/pkg/mod` を推測すると存在しない場合がある。依存ソースの読み取り許可は `.dev` 全体の読み取り許可ではなく、認証・制御・実状態ファイルは引き続き除外する。

## 進捗確認と会話の再利用

対話画面はANSI制御文字を含む差分出力なので、出力が空でも承認待ちでないとは限らない。停止が疑われる場合は `Ctrl+O` で詳細表示を切り替え、承認画面を確認する。スピナーの大量出力も調査の進捗を示すとは限らない。

長いコマンドや文章を入力する場合、入力とEnter送信を分け、候補選択で別のスラッシュコマンドが選ばれていないか確認する。実行中の追加メッセージはキューに入ることがあり、即座に反映されたと断定しない。

`--conversation ID` は保存会話の再開であり、稼働プロセスへのアタッチではない。同じ会話を別プロセスで同時操作しない。`--continue`（`-c`）は最新会話を選ぶため、対象を確実に指定する場合はIDを使う。

`/help` のgeneral画面で現在の会話ID、CLIバージョン、ログファイルを確認できる。再開指定のIDと画面のIDが異なることがあったため、対象の依頼・回答と現在のIDを照合する。ヘルプにはアカウント情報も表示されるので、出力をそのまま公開しない。

## 再生成せずに結果を取得する

対話画面で次を実行する。

```text
/copy
/copy n
```

`/copy` は直前の回答、`/copy n` は指定した回答をクリップボードへコピーする。今回、最終レビュー原文を `/copy` で取得できた。成功表示を確認してからクリップボードを読み、期待するレビュー本文か確認する。コピー失敗時に既存のクリップボード内容を結果として扱わない。

取得した原文はGit管理外の `.dev/reviews/` などへ保存する。再掲をモデルに依頼すると生成結果が変わる可能性があるため、原文取得には使わない。

会話全体の公式エクスポート機能は未確認。対話候補には `/export` がなく、CLIヘルプにも該当するサブコマンドは見つからなかった。会話は `~/.gemini/antigravity-cli/conversations/<ID>.db` に保存されているが、DBからの抽出手順は未検証。`--log-file` は診断ログの指定であり、会話全文の出力保証として扱わない。

将来非対話で実行する場合は `--output-format stream-json` で途中イベントを取得できる。これも承認問題を解決する機能ではない。記録にはプロンプト・ツール情報が含まれ得るため、保存先はGit管理外とし、必要部分だけ共有する。

結果取得後は `/exit` で対話CLIを終了できる。会話はIDを指定して再開できる。
