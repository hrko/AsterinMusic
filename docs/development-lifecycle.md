# 開発用Botの起動管理

> 検証・移行時点の記録です。現在の動作は[現行仕様](specification.md)、構成は[アーキテクチャ](architecture.md)、操作は[開発・運用手順](development.md)を参照してください。

2026-11-02。制限された環境からのプロセス確認が空だったことを停止と判断し、同じBotを複数起動した問題を受け、起動管理をGo製miseタスクへ集約した。

`bot-start`、`bot-stop`、`bot-restart`、`bot-status`、`bot-logs`を使用する。`serve`は`bot-start`の互換エイリアス。操作規則はルートのAGENTS.mdに記載した。

管理処理はプロジェクトのbinにあるrainmusic-voice系のプロセスを列挙し、PIDと実行ファイルを、認証付きlocalhost制御サーバーの応答と照合する。制御ファイルだけを稼働状態の根拠にしない。管理外・応答不能・調査不能・複数起動の場合は停止・起動を拒否し、自動で強制終了しない。WindowsではToolhelpとQueryFullProcessImageName、Linuxでは/procを使用する。

プロジェクトの絶対パスから決めたlocalhostポートをプロセス生存期間中保持して二重起動を防ぐ。別ポートで開発操作を排他制御する。ポート競合はエラーとして扱う。別チェックアウト・同じトークンを使う別ホストの起動までは管理しない。

再起動は別名の実行ファイルへビルドしてから停止を依頼する。停止要求は親コンテキストをキャンセルし、キュー保持・音声処理終了・Discordクライアント終了を通す。OS上の旧PID消失を確認した後だけ、新版を起動する。停止タイムアウト時は後続起動しない。起動成功はDiscord接続完了のready応答で判定する。

検証：

- Windowsの管理外Bot PIDを検出し、操作を拒否することを確認。
- Windowsでbot-startの再実行が同じPIDを維持し、二重起動しないことを確認。
- Windowsでbot-restartが旧PIDの終了後に新PID1つを起動し、ready=trueを返すことを確認。
- 制御サーバーの二重起動拒否、認証なし停止の拒否、正常終了要求、終了後の再取得を単体テスト。
- mise run check成功。通常版・SIMD版のWindows/Linuxクロスビルドを含む。
- WSL Linuxの競合検出付き全パッケージテスト成功。LinuxでのDiscord接続を伴うバックグラウンド起動は未検証。

移行前のプロセスは制御エンドポイントがなかったため、初回のみPID・パス・起動時刻を確認して停止した。以後の確認はすべて管理タスクを使用した。ログ・制御トークン・キューはGit管理外の.devに置く。
