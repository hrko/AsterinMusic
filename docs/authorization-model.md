# 認可モデルと導入時の許可表

本書は認可サービス、プリセット、設定形式を定める。実装・設定読込・各操作への適用は済んでいる。導入時の検証と稼働Botへの反映状況は[検証記録](authorization-evaluation.md)を参照する。

## サービス境界

`internal/authorization.Service`はアプリ独自の主体・操作・対象・事実を受け取り、許可、安定した理由分類、関連ポリシーID、設定版を返す。評価不能時はエラーも返す。利用側は許可が明示された場合だけ実行する。Cedarの型はインターフェースに含まない。

主体はサーバーID、ユーザーID、同じサーバー内のロールID、管理者・所有者属性で構成する。対象はサーバー、Bot、再生セッション、VC、必要なら曲の追加者を持つ。CedarのUserとRoleのIDにはサーバーIDを含める。異なるサーバーの主体と対象の組み合わせは評価前に拒否する。

事実には、取得完了、対象を閲覧可能、対象VCに参加、いずれかのVCに参加、を区別して保持する。取得失敗を空のロール集合に置き換えず、取得完了をfalseとして拒否する。Cedar評価中に外部I/Oは行わない。

## 基礎プリセット

| 設定名 | 運用方式 | 一般参加者の操作 |
|---|---|---|
| `collaborative` | 共同操作（既定） | 曲追加・再生操作 |
| `dj_control` | DJ操作・参加者選曲 | 曲追加。再生操作はDJ等のみ |
| `dj_control_self_skip` | DJ操作・参加者選曲＋本人スキップ | 曲追加と、自分が手動追加した再生中の曲のスキップ |
| `dj_only` | DJ専用 | 閲覧のみ。曲追加・再生操作はDJ等のみ |

DJ等は指定DJロール、Discord管理者、サーバー所有者を指す。再生操作は再開・停止・スキップ・全消去・音量変更・自動再生変更。曲追加には`/playnext`、付属リスト・Mix、履歴からの通常・優先再追加も含む。曲追加・再生操作には対象VCへの参加が必要で、DJ等も例外ではない。

全プリセットで、対象VCを閲覧できる利用者はキュー・再生中・音量・自動再生状態を閲覧できる。履歴閲覧は対象VCへの参加も要求する。履歴の再追加は閲覧とは別に認可するため、`dj_only`の一般参加者は閲覧できても再追加できない。

すべてのDJプリセットには1件以上のDJロール設定を要求する。管理者・所有者の許可も基礎ポリシーに含め、追加のforbidを優先する。旧名`dj`は廃止し、同じ動作には`dj_control`を指定する。旧名の設定は起動時・再起動前の検証でエラーになる。

本人スキップは曲の追加者IDで判定する。手動で取り込んだプレイリスト・Mix・履歴再追加も対象に含む。自動再生の有効化者は自動追加曲の本人スキップ権を得ない。曲がない場合や他人の曲も対象外。ポリシーの`context.ownTrack`は手動追加曲で追加者が主体と一致する場合だけtrueになる。判定後に曲・追加者・自動再生区分が変わった場合は操作を拒否する。

追加ポリシーで許可を広げても、Discordの閲覧制限、サーバー境界、画面所有者、世代・期限などの固定条件は解除しない。初期版の再生操作はVC参加と、接続中ならBotと同じVCへの参加を固定条件として残す。DJロールや追加permitだけで遠隔操作はできない。停止中キューの閲覧対象は最後に記録したVCとし、既定の再開・追加もそのVCへの参加を要求する。履歴は対象VCへの参加に加え、閲覧・接続権限を要求する。

旧保存データのキューに対象VCが記録されておらず、チェックポイントからも復元できない場合は、一般利用者には公開しない。Discord管理者またはサーバー所有者だけが、通常のポリシー評価を受けたうえで復旧操作を行える。追加のpermitやDJロールだけでこの制限を解除しない。管理者が参加したVCで再開・追加に成功すると、そのVCをキューの認可対象として保存する。非公開VCへのアクセス権がない利用者へ、推測で旧キューを引き渡さないための移行条件である。

## 制限と設定検証

追加ポリシーは最大100件、1件8KiB、合計64KiBとする。ロールは最大250件、ポリシーIDはASCII英数字と`._-`で最大64文字とし、`builtin.`は予約する。同じIDは重複不可。追加設定は1項目につき1つのCedarポリシーとする。

起動時には全ポリシーを構文・厳格スキーマ検証する。構文や型のエラーで部分適用しない。診断には安全なポリシーIDと失敗分類だけを返し、ポリシー原文は出力しない。実行時にもリクエスト・Entityを検証し、評価診断に1件でもエラーがあれば拒否する。

この制限で複雑な式の評価時間を保証するものではない。設定者は信頼された運用者に限定する。設定版はプリセット・ロール割当・ポリシー内容から計算し、ログに原文を含めずに評価時の設定を識別する。

## 設定形式

認可設定はサーバーごとの`servers.<名前>.authorization`に置く。省略時のpresetは`collaborative`、追加ルール・DJロールは空とする。将来複数Botを管理するときにも、サーバーの運用方式を同じ場所で定義できる。

```yaml
servers:
  home:
    id: "123456789012345678"
    bots: [main]
    command_bot: main
    authorization:
      preset: dj_control
      dj_role_ids: ["234567890123456789"]
      policies:
        - id: forbid_stop
          policy: |
            forbid(principal, action == Action::"playback.stop", resource);
```

これは形式の例であり、既存設定を置き換える指示ではない。ルールはYAMLの文字列として記述し、他の設定と同じ変数展開規則を適用する。外部ポリシーファイルや実行中の変更には初期版では対応しない。不明なキー、数値で記述したロールID、不正な構文・スキーマは設定読込時に拒否する。エラーにはルール本文を含めない。
