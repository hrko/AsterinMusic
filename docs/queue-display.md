# キューの表示と操作

通常キューと自動再生候補の一覧では、曲名の行末に半角スペース2個を付けて改行し、ページ先頭の番号幅に固定してインデントした補足行を `-# ` で始める。曲名と補足の間にも曲間にも空行を置かない。11番始まりの自動番号と、補足行のユーザーメンションをWebhookの実画面で確認済み。再生中の曲と単曲の結果表示では補足を通常の文字サイズに保つ。

レイアウトは上からタイトル「再生キュー」、本文内の再生中と曲一覧、自動再生の状態、フッター、操作ボタンとする。曲ごとのFieldは作らず、本文の1行目に番号・曲名リンク、次の行に時間・チャンネルリンク・追加者メンションを添える。チャンネル不明の場合はサイト名を使う。自動候補はサイトがページ内で共通なら一覧見出しへまとめ、異なる場合のみ各曲に補足する。曲名リンクは太字でUnicode幅56、チャンネル名は幅24までに省略する。書記素単位で切り、曖昧幅は1に固定する。画像は表示しない。再生中の文字数制限は維持する。番号は順序付きリストとし、補足行はページ先頭の番号幅に固定してインデントする。曲間の空行は省く。

手動キューのフッターは件数と合計時間を横並びにし、次行にページと「表示時点の再生予定順」を配置する。合計時間は「1時間23分」の形式（1時間未満は分・秒）とし、不明分の件数を併記する。自動候補のフッターはページと「取得済みの候補」「候補は変更・補充されます。」を表示する。

`/queue`は実行者だけに見えるEphemeral応答を返す。青系のEmbedに再生中（未送信なら再生準備中）の曲、一覧、自動再生状態を表示する。現在曲にサムネイルがある場合だけ右側に表示する。追加者はユーザーメンション形式で表示し、通知は無効化する。曲名は正規化した動画URLへのリンクとし、表示長を制限してMarkdown記号をエスケープする。各曲の長さとサイトも表示する。

手動の待機曲があれば、既存の再生予定順を1ページ10曲で表示する。順位はページ間で連番。フッターにはページ番号・総ページ数・待機曲全体の件数と合計時間を表示する。再生中の曲は集計に含めない。長さが不明な曲は既知分の合計とは別に件数を示す。ユーザー向けの表現は「再生予定順」とし、「公平な」は使用しない。

手動待機曲がなく自動再生がONなら、自動再生候補の一覧へ切り替える。再生履歴との重複を除き、選択される順に10曲ずつ表示する。候補であることは見出しで示し、各行に追加者は記載しない。各曲の長さは表示するが、候補の総件数・合計時間・総ページ数は表示しない。候補は補充されるため、フッターは「1ページ目」のように表示し、終了時刻を示唆しない。候補は手動追加・起点変更で変わる旨と起点曲を示す。候補なしの場合は、起点待ち・未取得・取得中・取得失敗を区別する。

「前へ」「次へ」「更新」は同じメッセージを最新状態で更新する。表示対象が手動と自動で切り替われば1ページ目へ戻し、ページ数が減った場合は最終ページへ補正する。移動できない方向のボタンは無効化し、空の状態でも更新は残す。`page`指定も継続する。定期更新は行わず、表示を閉じた場合は再度`/queue`を実行する。

ボタンはバージョン・実行者ID・表示対象・移動先ページを持つ。操作時にサーバーと実行者を検証する。閲覧にVC参加は不要で、Bot再起動後も表示が残っていればボタンから最新状態を再取得できる。閲覧はネットワークでの音源取得や候補の消費を行わない。「次へ」も取得済み範囲だけで有効になる。キュー消去は従来の`/queue action:clear`を使い、閲覧用ボタンには含めない。

更新はセッション単位で直列化し、本文とボタンを一緒に編集する。再生状態のロック下で表示用データを構築し、Discordへの送信時はそのロックを解放する。閲覧者ごとのページ位置はボタンに保持するため、別の人のページ送りには影響しない。

## 待機曲の編集

手動待機曲があれば「キューを編集」を表示する。対象VCへ参加し、追加者別の一覧で曲を選ぶと、番号の後に選択マーカーが付く。上・下・先頭・順番指定で同じ追加者内の位置を変え、削除でその待機項目だけを取り除く。削除は確認なしで実行し、直後は未選択に戻す。再生中の曲には適用しない。

他人の曲も操作できる場合は「追加者を変更」から箇条書きの追加者一覧を開く。各一覧は10件ずつ表示する。曲一覧の中央ページ番号からページを入力でき、移動で曲が別ページへ移ると選択とページが追従する。手動のページ切り替え・追加者変更では選択を解除する。「再生キューへ戻る」で全体の再生予定順に戻る。

編集結果は本人専用の元画面へ表示し、公開通知は送らない。画面の期限は作成から15分、保持上限は1,024画面で、操作によって延長しない。再起動・期限切れ後は開き直す。変更直前に最新の権限・対象・VCを確認し、移動対象の追加者内の順番が変わっていた場合は一覧を更新して再操作を求める。認可の許可表は[認可モデル](authorization-model.md)、詳細と検証条件は[キュー編集要件](queue-edit-plan.md)を参照する。
