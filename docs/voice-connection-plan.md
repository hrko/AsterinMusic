# 音声接続管理の見直し要件

## 位置づけと対象

本書は合意した変更要件であり、実装完了を示さない。現行の挙動は[仕様書](specification.md)、実装構成は[アーキテクチャ](architecture.md)を参照する。実装時には両文書を更新し、本書の検証条件との対応を記録する。

接続管理の実装と再生セッションへの組み込みを追加済み。実Discordでの往復・連続移動、待機中の移動、外部退出の確認は未完了であり、次の自動テストとは区別する。

実機確認では、移動後もVC所属は維持されたが音声が再開しなかった。移動先の所属を認識した後、接続情報待ちから接続確立中へ進まないことをログで確認した。接続先通知の未受信と重複判定による破棄を区別するため、所属通知とサーバー通知の受信・判定ログを追加した。トークン・セッションID・暗号鍵の値は記録しない。この事象の解消を確認するまで移動機能の実機検証は完了としない。

| 要件 | 自動検証 |
| --- | --- |
| 通知順序・往復・世代分離 | `voice_connection_test.go`で所属・サーバー・切断通知の6通りの順序、4014・4022、遅い完了と旧通知、停止・外部退出、期限と重複、4015 Resume、4021の打ち切り |
| ライブラリとの接続境界 | `voice_transport_test.go`でローカルTLS WebSocketとの実ハンドシェイク、発話通知、3接続分のUDP・DAVEの独立性、無効化後の送信拒否と資源解放 |
| 音声WebSocketの寿命 | `voice_socket_test.go`でHeartbeat応答・タイムアウト、4015後のResume、DAVEバイナリ送信、終了時に内部再接続しないこと |
| 再生内容の保持 | `voice_recovery_test.go`で現在の手動曲・自動曲、キュー順序、停止状態の管理保存、明示停止時の現在曲破棄 |
| 暗号化と周辺機能 | DAVE準備中の送信拒否・プロトコル0、既存の権限・通知・履歴・ビットレート・管理保存のテスト |

対象は、Discord音声接続の確立・VC移動・復旧・終了と、再生処理との境界である。イベントの到着順による退出や無音を防ぎ、接続の切り替え中も再生状態を保持する。キューの選曲規則、音源取得方式、複数Bot対応、新しいコマンドの追加は対象外とする。

## 再生セッションと接続管理の責務

再生セッションは音声接続管理を所有する。VC移動では再生セッションを維持し、その配下の通信接続を交換する。セッションの識別をVC IDそのものに依存させず、将来はBotアカウントとサーバーに対応する接続を割り当てられる構造とする。今回、同時再生できるVC数は変更しない。

| 担当 | 保持する状態と判断 |
| --- | --- |
| 再生セッション | 現在曲、待機キュー、再生位置、音量、自動再生設定、音源の取得・デコード・Opus変換、曲の失敗時の選曲 |
| 音声接続管理 | 最新の所属VC、接続先情報、接続状態、接続世代、復旧期限、WebSocket・UDP・DAVE、音声送信の可否 |

所属VC・接続世代・復旧期限の正本は音声接続管理に置く。再生側はその状態を参照し、独立した移動判定や復旧タイマーを持たない。履歴に保存する「再生開始時のVC」は、現在の所属とは別の記録として保持する。

一時的な接続切り替えは曲の失敗として返さない。接続管理は送信を待機させ、復旧期限を超えた場合に接続復旧失敗を通知する。再生側はそれを音源取得・デコードの失敗と区別し、曲のスキップや連続失敗回数への加算を行わず停止する。

## 利用者から見た動作

| 状況 | 動作 |
| --- | --- |
| 再生中に別VCへ移動 | 同じ曲の再生処理を保持し、移動先の準備後に途中から再開する |
| 音声接続の切り替え中 | 送信と再生位置の進行を待機する。短い無音は許容する |
| 往復・連続移動 | 最新の所属VCへ追従し、途中のVCへの接続試行は無効化する |
| 再生していない状態で移動 | 接続先を更新する。移動を理由に再生を開始しない |
| 復旧失敗 | 現在曲、待機キュー、音量、自動再生設定を保持して停止する。設定がONでも自動再生は利用者の再開操作まで進めない |
| 復旧失敗後のURLなし `/play` | 現在の権限・所属を確認して接続を確立し、保持した現在曲を先頭から再生する |
| Discord側からVC所属を解除された | 復旧を中止し、勝手に再参加しない。保持した再生内容は明示的な再開操作を待つ |
| 移動中に `/stop`・管理終了 | 停止・終了を優先する。遅れて届く通知から接続や再生を復活させない |

復旧失敗時の現在曲は、手動追加・自動追加のどちらも一度だけ保持する。待機キューへの重複挿入や順序変更を起こさない。明示的な停止・管理再起動の保存規則は現行仕様を維持する。

## 接続状態とイベントの判断

次の状態を区別する。名称は概念上のもので、型名や実装方式は指定しない。

| 状態 | 意味 |
| --- | --- |
| 未接続 | 接続を開始していない、または終了済み |
| 接続情報待ち | 所属と新しい接続先情報を待っている |
| 接続確立中 | WebSocket・UDP・DAVEを準備している |
| 送信可能 | 最新の接続で音声を送信できる |
| 復旧待ち | 接続喪失後に移動・退出・一時障害を判定している |
| 復旧失敗 | 自動復旧を終了し、利用者の操作を待っている |
| 終了処理中 | 接続と関連処理を閉じている |

再生中／停止中、自動再生ON／OFFは接続状態から独立させる。VC所属が残っていても通信接続が失われている場合があるため、所属と送信可能性を同一視しない。

接続状態を変更する判断を一か所に集約し、所属変更、サーバー情報更新、WebSocket切断、接続完了、期限切れ、停止要求を順序立てて処理する。次の条件を満たすこと。

- 切断コードだけで退出を決めず、最新の所属と接続処理の進行状況を照合する。
- 所属変更・サーバー更新・旧接続の切断は、到着順が異なっても扱える。新旧の接続情報を誤って組み合わせない。
- `4014`・`4022` では旧セッションをResumeしない。移動が確認できた場合は新しい接続情報で接続する。外部退出が確認できた場合は終了する。
- `4015`など復旧可能な障害は移動と区別し、コードに適した復旧方法を使う。認証・プロトコル拒否・レート制限を無条件の再接続ループにしない。
- 接続処理に世代を持たせる。旧世代の成功・失敗・DAVE処理・終了通知は、新世代を変更できない。
- 重複通知は接続や送信の二重起動を起こさない。終了した接続試行は遅い通知で復活しない。
- 旧通信接続の破棄とVCからの退出要求を分ける。移動の後始末が移動先からの退出を引き起こさない。

## 音声送信と資源の寿命

移動時は旧通信接続を終了し、新しいWebSocket・UDP・DAVEを準備する。同じendpointでも旧トークンや音声セッションを再利用しない。DAVEの旧VCの鍵、メンバー、保留中の遷移、復旧処理を新接続へ引き継がない。

最新の接続世代について、UDPと通信暗号鍵、DAVE、発話開始通知がそろってから音声を送る。暗号化準備中に平文へフォールバックしない。無効化済みの接続に新たなフレームを渡さない。無効化直前に送信済みのパケットは取り消せないため、移動境界で完全に無欠損の再生は保証しない。

接続待機は再生パイプラインにも伝え、有限の先読みバッファを超えて処理やメモリ使用量が進まないようにする。送信成功分だけ再生位置を進め、復旧後に待機分をまとめて高速送信しない。通常の移動成功では音源の再取得や曲の先頭への巻き戻しを行わない。

停止・期限切れ・世代交代では、待機中の処理と不要な接続資源を終了できること。通信I/Oや鍵交換待ちが、停止要求や新しい移動の処理を妨げないこと。

## 復旧期限

移動または接続喪失の検知から30秒を、一連の復旧の既定期限とする。接続情報待ち・通信確立・DAVE準備をこの期限に含める。同じ通知の重複や内部リトライで延長せず、実際に別VCへ再移動された場合だけ新しい期限を設定する。初期実装では利用者向け設定を追加しない。

期限切れ後の遅い接続完了では自動再開しない。人がいるVCから、復旧失敗だけを理由に自主退出しない。外部退出、明示的な停止、既存の無人退出条件は別途適用する。

## 権限・表示・保存との境界

- 操作権限は最新の所属VCで判断する。移動前に開始した追加処理も、反映時に権限と操作世代を確認する。
- 移動元のテキストチャンネルへの通知先を解除する。移動先の参加者による操作で通知先を設定し直す。
- 移動成功を毎回チャットに通知しない。復旧失敗は通知可能な宛先がある場合に案内する。失敗の詳細はログへ記録する。
- 無人判定は移動先でやり直す。人がいる間の既定の接続維持と、無人退出・任意の待機退出設定は維持する。
- 音量・自動再生設定・キュー順序を保持し、Opusの目標ビットレートは移動先に追従する。
- 現在曲の履歴は再生開始時のVCに残す。移動だけで追加記録せず、次の曲から移動先へ記録する。
- 管理再起動時は最新の所属と再生状態を整合した状態で保存する。接続復旧に失敗して停止したセッションを、再起動で自動再生させない。

## 検証と完了条件

自動テストでは時刻とイベント順序を制御し、実際の待ち時間やDiscordへの接続に依存せず、次の条件を再現できるようにする。

| 検証対象 | 確認する条件 |
| --- | --- |
| イベント順序 | 所属変更・サーバー更新・切断の順序違い、遅延、重複、同一endpointでのトークン変更 |
| 移動 | `4014`・`4022`を伴う片道・往復・連続移動、接続確立途中の再移動、再生していない状態の移動 |
| 世代の分離 | 旧接続の完了・失敗・DAVE通知が新接続へ影響しない、二重送信や接続資源の残留がない |
| 停止との競合 | 移動途中の `/stop`・管理終了・外部退出を優先し、後から復活しない |
| 復旧失敗 | 期限が重複通知で延びない、現在曲と設定が保持される、明示的な再開まで再生しない |
| 音声と周辺機能 | 待機中の再生位置・先読み上限、暗号化前の送信防止、権限・通知先・履歴・保存の境界 |

関連テスト、競合検査、Windows/Linux向けビルドに加え、実Discordで再生中の往復・連続移動、待機中の移動、外部退出を確認する。自動テストと実機確認の結果は区別して記録する。

ログには接続世代、状態遷移、対象VC、切断コード、復旧に要した時間、失敗段階を残す。接続トークンと暗号鍵は記録しない。最終的な判断基準は「最新の接続だけが送信できる」「停止後に復活しない」「復旧失敗で再生内容を失わない」の3点とする。

## 判断の根拠

- [Discord音声接続仕様](https://github.com/discord/discord-api-docs/blob/main/developers/topics/voice-connections.mdx)：所属・サーバー情報の待機、VC変更時のトークン変更と旧セッションの再利用禁止。
- [Discord音声切断コード](https://github.com/discord/discord-api-docs/blob/main/developers/topics/opcodes-and-status-codes.mdx)：`4014`・`4022`と`4015`の扱い。
- [discord.pyの接続管理](https://github.com/Rapptz/discord.py/blob/master/discord/voice_state.py)：`4014`・`4022`で移動の可能性を判定し、サーバー更新を待って新規接続する実装。
- [discord.jsの接続管理](https://github.com/discordjs/discord.js/blob/main/packages/voice/src/VoiceConnection.ts)：接続状態と破棄の区別、移動先情報による通信部分の交換。
