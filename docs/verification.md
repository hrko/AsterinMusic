## オフライン検証

- `mise run check`: 整形、`go vet`、単体テスト、Linux/Windows向けビルド成功。
- 公平なキュー: 再生中の新規参加、ユーザー内の順序、クリア後の再追加、古い終了通知の無視、同時追加時の容量制限・追加者情報。
- 音量: 0/30/50/100%、不正値、ステレオ均衡、10msフェード、PCM末尾の不完全フレーム検出。
- yt-dlpアダプター: URLの制限、動画・プレイリスト混在URLの単曲化、部分成功、ライブ拒否、不正JSON。
- プロセス: シェル特殊文字と日本語を含む引数、タイムアウトによる停止、エラー出力・標準出力のサイズ制限。
- `mise run audio-check`: 合成音声をデコード→Go音量処理→Opusエンコード→再デコード。30%のRMS振幅比は約0.03978（仕様値約0.03981、許容差5%以内）。0%は測定上0。キャンセル時に全ステージが終了。

通常のテストはネット接続・外部ツール不要です。FFmpegを使用するテストは`audio-check`で明示的に実行します。

## Discord・更新機構

- 自動再生：手動曲の開始による起点更新、自動曲・ニコニコによる起点維持、ON再実行の冪等性、履歴50曲とOFF後の保持、候補重複除外、手動優先、部分成功、候補取得の2回上限、取得中のOFF・停止・手動追加による古い結果の破棄をテスト。
- 再生ループのテストでは、自動追加曲の3連続失敗後に自動再生だけをOFFにし、途中で追加された手動曲を再生することを確認。WindowsのcheckとUbuntuのrace検査が成功。Discord上での自動補充・OFF・手動割り込みの手動受け入れ確認は別途必要。

- Mix追加：通常URLからのMix生成と既存Mixの維持、単曲取得との分離、部分成功、起点の扱い、ホスト名をまたぐ重複除外、件数境界をテスト。WindowsのcheckとUbuntuのrace検査が成功。`inspect-mix`では`PE_iyDsY5xM`の通常URLから100候補の取得に成功。DiscordでのMixコマンド・ボタンの手動受け入れ確認は別途必要。

- 設定したサーバー・チャンネルへのRESTアクセスと6個のスラッシュコマンド登録に成功。
- DAVE対応Windowsビルド、Gateway接続、3秒の低音量テスト音送信に成功。
- コマンドの同期処理がGatewayイベントを塞ぐ不具合を修正。非同期ディスパッチの回帰テストを追加し、利用者による実際の曲の再生を確認。
- プレイリストボタンの同時操作、本人制限、期限、再試行、重複1件の除外を単体テスト。
- yt-dlp 2026.10.26を独立した検証ディレクトリに取得し、公式SHA256・バージョン・公開動画のメタデータ取得を検証。その後mise管理版へのロールバック選択に成功。稼働Botは開発用の固定版を使用。
- 実時間ペーシングを伴う5秒のOpusパケット送信経路を追加検証し、最後まで正常終了。
- 利用者の報告したYouTube動画`PE_iyDsY5xM`では、取得と送信を直結した状態で165秒時点のダウンロード切断・再試行上限を再現。容量制限付き一時ファイルへの並行先読みを追加した後、12,730パケット・254.60秒分を4分17秒で最後まで処理し正常終了。
- 同じ修正を反映したDiscord Botでも、利用者が曲の最後までの再生を確認。

## 未検証・制限

- 2026-11-02：ライブ再生の音量適用とOpus変換を送信直前へ移動。WindowsとWSL Ubuntuで`native-audio-check`が成功。実際のOpusパケットをFFmpegで再デコードし、ミュートが40ms以内、復帰が80ms以内に現れることを確認。設定変更から次の送信コールバックまでWindows約20.3ms、Linux約19.8ms。Discordクライアントの再生遅延はこの測定に含まない。
- 同テストで80msの送信停滞を注入し、取り戻すための連続送信をしないこと、最新の音量設定を採用すること、キャンセル後に追加パケットを送らないこと、曲末の遅延分を出力することを確認。新経路の長時間運転・高CPU負荷時の遅延上限・Discord上での聴感確認は別途必要。音量適用後のアプリ内キューはなく、音量適用前のPCMは固定長フレームとOSパイプで保持する。FFmpeg内部を含めたPCM先読み量の厳密な1秒上限は未計測。

- WSL Ubuntu上でmise 2026.10.3からロック済みGo・FFmpeg・Zig・libdaveを導入。全パッケージの`go test -race ./...`と、音量・ミュート・キャンセル・実時間Opus処理のFFmpeg統合テストが成功。DAVE対応ネイティブビルドと動的ライブラリをロードしての起動にも成功。LinuxからのDiscord実接続は未検証。
- Windowsのrace detectorはZigとのリンク調整後、ThreadSanitizerのメモリ確保エラー（コード87）で起動に失敗。通常の並行操作テストは成功。
- プレイリストは偽のCLI出力とYouTubeの公開リストで検証。YT Music専用カタログ・プレイリストは未検証。
- 上限100件ちょうどの場合も`limit_reached=true`になります。「100件を超えることを確認した」という意味ではありません。
- yt-dlpが出力しなかった削除済み項目は集計できず、`skipped`はJSONとして受け取って除外した件数です。
- Windowsのプロセスツリー終了は`taskkill`に依存します。親プロセスが先に異常終了して子が残るケースは保証していません。運用前にJob Object方式を検討します。
- 複数人での実チャンネルの公平性、ボタン操作一式、長時間運転は手動の受け入れ確認が残っています。
